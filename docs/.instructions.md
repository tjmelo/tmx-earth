## 📋 Architecture Overview

### Core Structure
```
State (Redux) ←→ Components (React) ←→ API Service (Axios)
     ↓              ↓                        ↓
   Slice       ListCountries           REST Countries
             + InfoCountries
             + MountList
```

### Key Components

#### ListCountries.tsx
- **Type:** Container/Selector Component
- **Responsibility:** Fetch and display countries dropdown
- **State:** Uses Redux dispatch `update(countryName)`
- **Hook:** `useQuery('requestAll', toRequestAll)` from React Query
- **File Location:** `src/components/ListCountries.tsx`

#### InfoCountries.tsx
- **Type:** Display/Details Component
- **Responsibility:** Show selected country information
- **State:** `useSelector(state => state.country.country)`
- **Effect:** Fetches country details when selection changes
- **File Location:** `src/components/Countries/InfoCountries.tsx`

#### Redux Store
- **Location:** `src/store/store.ts`
- **Slices:** `src/feature/country/countrySlice.ts`
- **Reducer Actions:** `update(payload)`
- **State Shape:** `{ country: { country: string | [] } }`

#### API Layer
- **Config:** `src/model/api.ts` (Axios instance)
- **Services:** `src/service/request.ts`
- **Functions:**
  - `toRequestAll()` → GET /all
  - `toRequestOne(country)` → GET /name/{country}?fullText=true

### Type System
- **Location:** `src/interfaces/index.ts`
- **Key Types:**
  - `TListData` - Complete country information
  - `ICommonName` - Country name + flag
  - `TCurrencies` - Currency structure
  - `TName` - Multilingual name object

## 🛠️ Development Patterns & Conventions

### Component Pattern
```typescript
// src/components/ComponentName/ComponentName.tsx
import React from 'react'
import { useSelector, useDispatch } from 'react-redux'
import { someAction } from '../../feature/feature-name/featureSlice'

export const ComponentName = () => {
  const dispatch = useDispatch()
  const state = useSelector(selector)
  
  const handleAction = () => {
    dispatch(someAction(payload))
  }
  
  return (
    <div className="container">
      {/* JSX here */}
    </div>
  )
}

export default ComponentName
```

### Redux Slice Pattern
```typescript
// src/feature/feature-name/featureSlice.ts
import { createSlice } from '@reduxjs/toolkit'

const featureSlice = createSlice({
  name: 'featureName',
  initialState: {
    data: [],
    status: 'idle',
    error: null,
  },
  reducers: {
    setData: (state, action) => {
      state.data = action.payload
    },
    setStatus: (state, action) => {
      state.status = action.payload
    },
  },
})

export const { setData, setStatus } = featureSlice.actions
export default featureSlice.reducer
```

### API Service Pattern
```typescript
// src/service/feature.ts
import { api } from '../model/api'

export const toRequestFeatureData = async (params?: any) => {
  const { data, status } = await api.get('/endpoint', { params })
  return { data, status }
}

export const toRequestFeatureDetail = (id: string) => {
  return api.get(`/endpoint/${id}`)
}
```

### Test File Pattern
```typescript
// src/components/ComponentName/__tests__/ComponentName.spec.tsx
import { render, screen } from '@testing-library/react'
import { Provider } from 'react-redux'
import store from '../../../store/store'

  it('should render without errors', () => {
    render(
      <Provider store={store}>
        <ComponentName />
      </Provider>
    )
    expect(screen.getByText(/expected/i)).toBeInTheDocument()
  })
})
```

### Styling Pattern
```typescript
// Component with module styles
import styles from '../styles/components.module.scss'

export const MyComponent = () => (
  <div className={styles.containerClass}>
    {/* content */}
  </div>
)

// Or inline for Shadow DOM
import { css } from '@emotion/css'

  color: blue;
  font-size: 16px;
```

## 🔄 Working with Redux

### Creating a New Slice
1. **File:** `src/feature/[featureName]/[featureName]Slice.ts`
2. **Pattern:** Use `createSlice` from `@reduxjs/toolkit`
3. **Initial State:** Define all possible states clearly
4. **Reducers:** Keep mutations simple and focused
5. **Register:** Add to `src/store/store.ts` reducer config

### Using in Components
```typescript
import { useSelector, useDispatch } from 'react-redux'
import { someAction } from '../feature/featureName/featureSlice'

// Select state
const data = useSelector(state => state.featureName.data)

// Dispatch action
const dispatch = useDispatch()
dispatch(someAction(payload))
```

### Async Operations (Thunks)
For async operations, use `createAsyncThunk`:
```typescript
export const fetchData = createAsyncThunk(
  'featureName/fetchData',
  async (_, { rejectWithValue }) => {
    try {
      const response = await api.get('/endpoint')
      return response.data
    } catch (error) {
      return rejectWithValue(error.message)
    }
  }
)
```

```typescript
try {
  const { data } = await api.get('/endpoint')
  // Use data

  if (error.response?.status === 404) {
    // Handle 404
  } else if (error.code === 'ECONNABORTED') {
    // Handle timeout (10s configured)
  } else {
    console.error(error)
  }
}
```

## 🎨 Styling Guidelines

### Global Styles
- Location: `src/styles/global.scss`
- Usage: Applied to entire application
- For constants (colors, breakpoints): Use CSS variables

### Component Styles
- Location: `src/styles/components.module.scss`
- Usage: `import styles from '../styles/components.module.scss'`
- Pattern: One class per component grouping

### CSS Preprocessor
- Format: SCSS (Sass)
- Nesting: Use sparingly (max 3 levels)
- Variables: Use $variable syntax

### Shadow DOM Integration
- Styles injected via: `src/utils/styleScope.ts`
- Bootstrap & custom styles included
- Prevents CSS conflicts with parent app

## ⚠️ Common Pitfalls to Avoid

1. **Direct State Mutation** - Always use Redux reducers, never mutate state
2. **Missing Type Annotations** - All props and returns should be typed
3. **No Error Boundaries** - Wrap feature sections with error boundaries
4. **Unhandled Promise Rejections** - Always use try/catch or .catch()
5. **Memory Leaks** - Clean up subscriptions in useEffect cleanup
6. **Shadow DOM CSS Issues** - Remember styles don't inherit into Shadow DOM
7. **Accessibility Oversights** - Test with keyboard navigation
8. **No Tests for New Code** - Write tests alongside features
